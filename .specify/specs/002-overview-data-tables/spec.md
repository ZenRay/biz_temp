## User Scenarios & Testing *(mandatory)*

### User Story 1 - 四级类目数据概览 (Priority: P1)

运营人员在概览页面查看四级类目维度的数据表格，了解各品类的整体表现。表格展示品类名称（ID-名称格式）、目标等级、达成等级、曝光门店数、登录店铺数、曝光店铺数、曝光转化率、货值、货值目标、达成率、货值占比、日活、日活覆盖率、下单件数、客均件数、平台盈余金额、平台毛利率等核心指标。部分 Top 榜单相关字段（如 Top1 品类曝光门店数、Top1 曝光品类、跨中心仓 Top1 相关指标）暂时无数据，但表头需要呈现。表格位于独立的 PageSection 中，右侧 TOC 可快速跳转到该 section。

**Why this priority**: 四级类目是复盘的起点，运营人员需要从品类维度快速定位异常。这是概览页的核心功能，必须优先实现。

**Independent Test**: 打开概览页面，选择日期范围后，四级类目表格能正常加载并展示数据。表格包含所有定义的列，Top 相关列显示为空或占位符。支持分页、排序、筛选器联动。右侧 TOC 显示"四级类目"项，点击后平滑滚动到该表格。

**Acceptance Scenarios**:

1. **Given** 用户进入概览页面，**When** 页面加载完成，**Then** 四级类目表格显示第一页数据（默认 20 条），位于"四级类目"section 中
2. **Given** 四级类目表格已加载，**When** 用户查看表头，**Then** 显示所有定义的列（包括 Top 相关列，即使数据为空）
3. **Given** 用户在筛选器中选择四级类目"红富士苹果"，**When** 筛选器确认，**Then** 表格过滤为红富士苹果品类数据
4. **Given** 四级类目表格已加载，**When** 用户点击"货值"列头，**Then** 表格按货值升序/降序排列
5. **Given** 四级类目表格已加载，**When** 用户点击"下一页"，**Then** 表格切换到第 2 页
6. **Given** 用户查看右侧 TOC，**When** 点击"四级类目"，**Then** 页面平滑滚动到四级类目表格 section

### User Story 2 - 商家四级类目数据概览 (Priority: P1)

运营人员在概览页面查看商家×四级类目维度的数据表格，了解各商家在特定品类下的表现。表格展示四级类目名称（ID-名称格式）、商家名称（ID-名称格式）、目标等级、达成等级、曝光门店数、登录店铺数、曝光店铺数、品类曝光门店数、曝光转化率、货值、货值目标、达成率、货值占比、日活、日活覆盖率、下单件数、客均件数、平台盈余金额、平台毛利率等指标。部分 Top 榜单相关字段暂时无数据，但表头需要呈现。表格位于独立的 PageSection 中，右侧 TOC 可快速跳转到该 section。

**Why this priority**: 商家×品类维度是诊断商家表现的关键，运营人员需要快速定位哪些商家在哪些品类上表现异常。与四级类目表同等重要。

**Independent Test**: 打开概览页面，商家四级类目表格能正常加载。表格包含所有定义的列，Top 相关列显示为空或占位符。支持分页、排序、筛选器联动。右侧 TOC 显示"商家四级类目"项，点击后平滑滚动到该表格。

**Acceptance Scenarios**:

1. **Given** 用户进入概览页面，**When** 页面加载完成，**Then** 商家四级类目表格显示第一页数据，位于"商家四级类目"section 中
2. **Given** 商家四级类目表格已加载，**When** 用户查看表头，**Then** 显示所有定义的列（包括 Top 相关列）
3. **Given** 用户在筛选器中选择商家"林果"，**When** 筛选器确认，**Then** 表格过滤为林果的数据
4. **Given** 商家四级类目表格已加载，**When** 用户点击"达成率"列头，**Then** 表格按达成率排序
5. **Given** 用户查看右侧 TOC，**When** 点击"商家四级类目"，**Then** 页面平滑滚动到商家四级类目表格 section

### User Story 3 - 商品数据概览 (Priority: P1)

运营人员在概览页面查看商品维度的数据表格，了解各 SKU 的详细表现。表格展示四级类目名称（ID-名称格式）、商家名称（ID-名称格式）、商品名称（ID-名称格式）、目标等级、达成等级、曝光门店数、登录店铺数、曝光店铺数、品类曝光门店数、曝光转化率、货值、货值目标、达成率、货值占比、日活、日活覆盖率、下单件数、客均件数、平台盈余金额、平台毛利率等指标。部分 Top 榜单相关字段暂时无数据，但表头需要呈现。表格位于独立的 PageSection 中，右侧 TOC 可快速跳转到该 section。

**Why this priority**: 商品维度是最细粒度的数据，运营人员需要定位到具体 SKU 的诊断。与四级类目表、商家四级类目表同等重要。

**Independent Test**: 打开概览页面，商品表格能正常加载。表格包含所有定义的列，Top 相关列显示为空或占位符。支持分页、排序、筛选器联动。右侧 TOC 显示"商品"项，点击后平滑滚动到该表格。

**Acceptance Scenarios**:

1. **Given** 用户进入概览页面，**When** 页面加载完成，**Then** 商品表格显示第一页数据，位于"商品"section 中
2. **Given** 商品表格已加载，**When** 用户查看表头，**Then** 显示所有定义的列（包括 Top 相关列）
3. **Given** 用户在筛选器中选择商品"红富士苹果 特级 75mm"，**When** 筛选器确认，**Then** 表格过滤为该商品的数据
4. **Given** 商品表格已加载，**When** 用户点击"平台毛利率"列头，**Then** 表格按平台毛利率排序
5. **Given** 用户查看右侧 TOC，**When** 点击"商品"，**Then** 页面平滑滚动到商品表格 section

### User Story 4 - 筛选器联动与数据刷新 (Priority: P2)

用户在概览页面通过筛选器选择日期窗口、日期范围、四级类目、商家、商品后，三个表格同步刷新，展示过滤后的数据。筛选器状态通过 URL 参数同步，刷新页面或分享链接时筛选条件不丢失。

**Why this priority**: 筛选器是数据探索的核心交互手段，三个表格需要联动响应筛选器变化。这是概览页的基础能力。

**Independent Test**: 在概览页选择日期窗口和四级类目，验证三个表格同步刷新。刷新页面，验证筛选器回显正确。

**Acceptance Scenarios**:

1. **Given** 用户在概览页面，**When** 选择日期窗口"近 7 天"并确认，**Then** 三个表格同步刷新为近 7 天数据
2. **Given** 用户在概览页面，**When** 选择四级类目"红富士"并确认，**Then** 三个表格过滤为红富士品类数据
3. **Given** 用户已选择筛选条件，**When** 刷新页面，**Then** 筛选器自动回显之前选择的值，表格数据一致
4. **Given** 用户复制当前 URL 在新标签页打开，**When** 页面加载，**Then** 筛选器自动回显，表格数据一致

---

### User Story 5 - 表格交互与数据展示 (Priority: P2)

概览页面的三个表格支持分页（默认每页 20 条）、列排序（点击表头切换升序/降序/默认）、全屏放大（点击全屏按钮弹出居中弹窗）。表格表头吸顶，滚动时始终可见。部分 Top 相关字段暂无数据时，显示为空或"-"占位符。

**Why this priority**: 表格交互是数据查看的基础能力，分页、排序、全屏放大提升数据探索效率。

**Independent Test**: 点击表格的"货值"列头，验证排序功能。点击全屏按钮，验证弹窗弹出。点击"下一页"，验证分页功能。

**Acceptance Scenarios**:

1. **Given** 用户查看四级类目表格，**When** 点击"货值"列头，**Then** 表格按货值升序排列，列头显示向上箭头
2. **Given** 表格已按"货值"升序排列，**When** 用户再次点击"货值"列头，**Then** 表格按货值降序排列，列头显示向下箭头
3. **Given** 用户查看表格，**When** 点击全屏按钮，**Then** 弹窗居中显示，展示完整表格
4. **Given** 表格中某行的 Top 相关字段无数据，**When** 用户查看该单元格，**Then** 显示为空或"-"占位符

---

### Edge Cases

- 筛选器选项为空时（如无商家数据），下拉框显示"暂无数据"，不报错
- 表格数据为空时，显示"暂无数据"占位提示，分页器隐藏
- URL 参数包含无效的 ID（如 categoryLevel4Id=9999），页面正常加载，筛选器显示"未知"，表格显示空状态
- 网络请求失败时，显示友好的错误提示和重试按钮
- 页面快速连续切换筛选器时，只显示最新一次请求的结果（避免竞态）
- Top 相关字段暂无数据时，表头正常显示，单元格显示为空或占位符，不影响其他列的数据展示
- 日期窗口选择后，表格数据按日期范围聚合（近 7/15/30 天）

- **FR-009**: 跨中心仓 Top1 曝光转化率商城品类 MUST 以"商城\n四级类目名称"格式显示

- **FR-012**: Top1 同品类曝光转化率商品名称 MUST 以"商家名称\n商品名称"格式显示
- **FR-013**: 跨中心仓 Top1 商家四级类目曝光转化率商家品类 MUST 以"商城\n商家\n四级类目名称"格式显示
- **FR-014**: 跨中心仓 Top1 商家品类曝光转化率商家品类 MUST 以"商城\n商家\n四级类目名称"格式显示

**数据来源与计算**：

- **FR-015**: 曝光门店数、商城登录店铺数、商城曝光店铺数 MUST 从商城 ADS 数据获取
- **FR-016**: 品类曝光门店数 MUST 从四级类目 ADS 数据获取
- **FR-017**: 曝光转化率 MUST 按公式计算：下单店铺数 / 曝光店铺数
- **FR-018**: 货值目标达成率 MUST 按公式计算：货值 / 货值目标
- **FR-019**: 客均件数 MUST 按公式计算：下单件数 / 下单店铺数
- **FR-020**: 平台盈余金额 MUST 按公式计算：平台抽佣金额 - 平台承担赔付金额 - 平台补贴金额
- **FR-021**: 平台毛利率 MUST 按公式计算：平台盈余金额 / 货值
- **FR-022**: 日活覆盖率 MUST 按公式计算：下单店铺数 / 一级类目下单店铺数（需 JOIN 商城一级类目表）
- **FR-023**: 货值占比 MUST 按粒度分层计算：商品货值 / 商家四级类目货值（商品表）、商家四级类目货值 / 四级类目货值（商家表）、四级类目货值 / 商城一级类目货值（品类表）

**筛选器与交互**：

- **FR-024**: 筛选器 MUST 包含日期窗口（近 7 天 / 近 15 天 / 近 30 天）、日期范围、四级类目、商家、商品五个维度
- **FR-025**: 筛选器选择确认后，三个表格 MUST 同步刷新
- **FR-026**: 筛选器状态 MUST 通过 URL query params 管理，刷新页面或分享链接时筛选条件不丢失
- **FR-027**: 所有表格 MUST 支持分页，默认每页 20 条
- **FR-027a**: 四级类目表 MUST 固定第一列（四级类目名称），其余列可水平滚动
- **FR-027b**: 商家四级类目表 MUST 固定第二列（商家名称），第一列（四级类目名称）可隐藏（水平滚动时自动隐藏），默认排序为四级类目
- **FR-027c**: 商品表 MUST 固定第三列（商品名称），前两列（四级类目名称、商家名称）可隐藏（水平滚动时自动隐藏），默认排序为四级类目、商家
- **FR-028**: 表格表头 MUST 吸顶（sticky），滚动时始终可见
- **FR-029**: 表格 MUST 支持列排序，点击表头切换升序/降序/默认，排序状态通过箭头图标指示
- **FR-030**: 表格 MUST 支持全屏放大功能，点击全屏按钮弹出居中弹窗。弹窗 MUST 支持缩放（最小为初始大小，最大填满页面 100%）；MUST 支持三种关闭方式（ESC 键、点击弹窗外部、关闭按钮）；弹窗内表格 MUST 保留分页和独立滚动功能

**页面布局**：

- **FR-030a**: 概览页面 MUST 采用垂直堆叠布局，三个表格分别位于独立的 PageSection 中（四级类目、商家四级类目、商品）
- **FR-030b**: 右侧 TOC MUST 自动生成，显示三个 section 标题，点击后平滑滚动到对应表格
- **FR-030c**: 每个 PageSection MUST 包含标题和简要说明，描述该表格的用途和核心指标

**加载状态与错误处理**：

- **FR-030d**: 每个表格 MUST 独立显示加载状态（loading spinner），避免一个表格的加载延迟阻塞其他表格的展示
- **FR-030e**: 某个表格加载失败时，仅该表格显示错误提示和重试按钮，其他表格正常展示
- **FR-030f**: 重试按钮点击后，仅重新加载失败的表格数据，不影响其他表格

**后端 API**：

- **FR-031**: 后端 MUST 提供概览页面数据 API，支持按日期范围、四级类目、商家、商品筛选
- **FR-032**: 后端 MUST 从 ADS 同步表（ads_category_daily、ads_merchant_category_daily、ads_sku_daily）获取原始数据
- **FR-033**: 后端 MUST 从目标表（biz_category_target、biz_merchant_category_target、biz_sku_target）获取目标数据，计算达成率
- **FR-034**: 后端 MUST 在 API 层完成计算逻辑（曝光转化率、货值目标达成率、客均件数、平台盈余金额、平台毛利率、日活覆盖率、货值占比）
- **FR-035**: 后端 MUST 支持日期窗口聚合（近 7/15/30 天），聚合逻辑按指标类型区分：存量指标（曝光门店数、登录店铺数等）显示窗口内最新一天的值；流量指标（货值、下单件数、平台盈余金额等）求和；比率指标（曝光转化率、货值目标达成率、客均件数、平台毛利率、日活覆盖率、货值占比）基于聚合后的流量指标重新计算
- **FR-035a**: 筛选器日期切换时，表格数据 MUST 同步切换为对应日期范围的数据
- **FR-035b**: 表格内 MUST 提供额外的日期窗口选择器（近 7/15/30 天），用于查看长周期聚合数据；切换窗口时数据重新聚合，但不影响筛选器日期
- **FR-036**: 后端 MUST 支持分页和排序参数

**数据库**：

- **FR-037**: 数据库 MUST 创建 ADS 同步表（ads_category_daily、ads_merchant_category_daily、ads_sku_daily）的镜像表
- **FR-038**: 数据库 MUST 创建目标表（biz_category_target、biz_merchant_category_target、biz_sku_target）的镜像表
- **FR-039**: 数据库 MUST 创建必要的索引支撑查询性能（日期、四级类目、商家、商品维度）

### Key Entities

- **四级类目（Category Level 4）**: 品类分类的最基础维度，属性包括 ID、名称、目标等级、达成等级、曝光门店数、登录店铺数、曝光店铺数、曝光转化率、货值、货值目标、达成率、货值占比、日活、日活覆盖率、下单件数、客均件数、平台盈余金额、平台毛利率。与商家存在多对多关系。
- **商家（Merchant）**: 商家实体，经营一个或多个品类。属性包括 ID、名称、目标等级、达成等级、曝光门店数、登录店铺数、曝光店铺数、品类曝光门店数、曝光转化率、货值、货值目标、达成率、货值占比、日活、日活覆盖率、下单件数、客均件数、平台盈余金额、平台毛利率。与四级类目存在多对多关系。
- **商品（SKU）**: 最小商品单元，归属于特定商家和品类。属性包括 ID、名称、目标等级、达成等级、曝光门店数、登录店铺数、曝光店铺数、品类曝光门店数、曝光转化率、货值、货值目标、达成率、货值占比、日活、日活覆盖率、下单件数、客均件数、平台盈余金额、平台毛利率。与商家和四级类目存在多对一关系。
- **筛选条件（FilterState）**: 用户选择的筛选参数组合，包括日期窗口、日期范围、四级类目、商家、商品。通过 URL query params 管理。
