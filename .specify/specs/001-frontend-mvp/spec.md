## User Scenarios & Testing *(mandatory)*

### User Story 1 - 全局概览与快速定位 (Priority: P1)

运营人员打开 Dashboard 后，首先看到概览页的数据明细表格，通过表格浏览全局数据，支持下钻到具体品类/商家/商品。

**Why this priority**: 概览页是复盘起点，承载"先看全局"的诊断步骤。如果概览无法快速呈现全局数据，后续所有下钻分析都无法开展。这是 10 名运营人员每日必用的核心入口。

**Independent Test**: 打开概览页，确认趋势图可交互，确认表格可分页浏览。可独立验证全局数据呈现能力。

**Acceptance Scenarios**:

1. **Given** 用户进入概览页，**When** 页面加载完成，**Then** 数据明细表格显示第一页（20 条）
2. **Given** 用户在概览页，**When** 选择日期窗口为"近 7 天"并确认，**Then** 趋势图、表格数据同步更新为近 7 天范围
3. **Given** 用户在概览页，**When** 选择四级类目为"红富士"并确认，**Then** 所有数据模块过滤为红富士品类数据
4. **Given** 用户在概览页查看表格，**When** 点击"下一页"，**Then** 表格切换到第 2 页，分页指示器更新为"第 2 页，每页 20 条"

---

### User Story 2 - 交互式下钻诊断 (Priority: P1)

运营人员在概览页发现某品类异常后，点击品类名称跳转到品类分析页。在品类分析页中，看到品类维度的指标、趋势和明细表格。表格中点击商家名称或品类名称，跳转到商家品类分析页。继续点击商品名称，跳转到商品分析页。整个下钻路径为：品类 → 商家 → SKU。

**Why this priority**: 交互式下钻是诊断框架工具化的核心能力。将"品类 → 商家 → SKU → 区县 → 门店"的下钻路径转化为点击即跳转的交互，直接缩短复盘时间。

**Independent Test**: 从概览页点击品类名称，验证跳转到品类分析页且筛选器自动填充。从品类分析页点击商家名称，验证跳转到商家品类分析页。全程 URL 参数正确传递。

**Acceptance Scenarios**:

1. **Given** 用户在概览页，**When** 点击表格中品类名称"红富士"，**Then** 跳转到品类分析页，URL 为 `/category/analysis?categoryLevel4Id=1001`，筛选器自动显示"1001-红富士"
2. **Given** 用户在品类分析页，**When** 点击商家品类表格中商家名称"商家A"，**Then** 跳转到商家品类分析页，URL 为 `/merchant/analysis?categoryLevel4Id=1001&merchantId=2001`，筛选器自动填充
3. **Given** 用户在商家品类分析页，**When** 点击商品表格中的跳转按钮，**Then** 跳转到商品分析页，URL 为 `/product/analysis?categoryLevel4Id=1001&merchantId=2001&skuId=3001`
4. **Given** 用户通过导航栏直接进入商家品类分析页，**When** 手动选择筛选条件，**Then** URL 参数同步更新，数据刷新

---

### User Story 3 - 筛选器联动与 URL 同步 (Priority: P1)

所有页面的筛选器常驻顶部吸顶显示，支持日期窗口（7/15/30 天）、日期范围、四级类目、商家、商品五个维度。筛选器选择后 URL 参数同步更新，用户刷新页面或分享链接时筛选条件不丢失。不同页面根据维度层级显示不同的筛选器组合。

**Why this priority**: 筛选器是数据探索的核心交互手段，URL 同步确保可分享、可后退，是 BI 看板的基础能力。

**Independent Test**: 在品类分析页选择四级类目和日期窗口，验证 URL 参数更新。刷新页面，验证筛选器回显正确。复制 URL 到新标签页打开，验证筛选条件一致。

**Acceptance Scenarios**:

1. **Given** 用户在品类分析页，**When** 选择日期窗口"近 15 天"、四级类目"1001-红富士"，点击确认，**Then** URL 更新为 `?categoryLevel4Id=1001`，数据刷新
2. **Given** 用户复制当前 URL 在新标签页打开，**When** 页面加载，**Then** 筛选器自动回显之前选择的值，数据一致
3. **Given** 用户在概览页（显示全部筛选器），**When** 切换到品类分析页，**Then** 只显示日期窗口、日期、四级类目三个筛选器，商家和商品筛选器隐藏
4. **Given** 筛选器下拉框展开，**When** 用户输入关键词"红"，**Then** 下拉选项过滤为包含"红"的选项（如"1001-红富士"）

---

### User Story 4 - 页面内导航与布局框架 (Priority: P2)

页面采用左侧可收起导航栏 + 顶部筛选器 + 右侧 TOC 三栏布局。导航栏通过点击面包屑或顶部按钮手动收起/展开。右侧 TOC 根据 PageSection 自动生成，点击 TOC 项平滑滚动到对应 section。内容区分为"指标概览"、"趋势分析"、"数据明细"三个 section。

**Why this priority**: 布局框架是所有页面的基础，导航和 TOC 影响用户在不同页面间的切换效率和长页面的定位能力。

**Independent Test**: 点击导航栏收起按钮，验证导航栏收起、内容区扩展。在品类分析页查看右侧 TOC，点击"趋势分析"，验证平滑滚动到对应 section。

**Acceptance Scenarios**:

1. **Given** 页面加载完成，**When** 用户点击顶部控制栏的收起按钮，**Then** 导航栏收起（宽度变为 0），内容区占满宽度
2. **Given** 导航栏已收起，**When** 用户点击面包屑区域，**Then** 导航栏重新展开
3. **Given** 页面包含 ≥1 个 PageSection，**When** 页面渲染完成，**Then** 右侧 TOC 显示所有 section 标题
4. **Given** 用户点击 TOC 中的"数据明细"，**When** 点击生效，**Then** 页面平滑滚动到"数据明细"section
5. **Given** 页面为诊断页（placeholder，无 PageSection），**When** 页面渲染，**Then** 右侧 TOC 不显示

---

### User Story 5 - 表格全屏放大与数据查看 (Priority: P2)

表格和可视化图右上角有全屏按钮，点击后弹出居中弹窗，展示该对象的完整内容。弹窗支持缩放（最多 100% 填满页面，最少恢复到初始大小）。弹窗内表格保留分页功能，可独立滚动。点击弹窗外部或按 ESC 关闭弹窗。

**Why this priority**: 全屏放大解决"数据展示空间不足"的痛点，让用户在需要深入查看细节时获得最大展示面积。

**Independent Test**: 点击表格的全屏按钮，验证弹窗弹出且居中。点击放大按钮，验证弹窗增大。按 ESC，验证弹窗关闭。

**Acceptance Scenarios**:

1. **Given** 用户查看数据明细表格，**When** 点击表格右上角全屏按钮，**Then** 弹窗居中显示，展示完整表格内容
2. **Given** 弹窗已打开，**When** 用户点击放大按钮，**Then** 弹窗增大（最多填满页面 100%），达到上限时放大按钮失效
3. **Given** 弹窗已打开（处于初始大小），**When** 用户查看缩小按钮，**Then** 缩小按钮失效（因为已是初始大小，无法再缩小）
4. **Given** 弹窗已打开，**When** 用户按 ESC 键或点击弹窗外部，**Then** 弹窗关闭，回到正常视图
5. **Given** 弹窗内展示表格，**When** 用户点击"下一页"，**Then** 弹窗内表格翻页，不影响外部页面

---

### User Story 6 - 趋势图交互与日期拖拽 (Priority: P3)

趋势图（x 轴为日期）在放大弹窗中显示日期拖拽功能（dataZoom），用户可拖拽选择日期范围。非放大状态不显示拖拽。图表显示 tooltip 和数据标签，数据标签使用深色（dark black）。

**Why this priority**: 趋势图是诊断"异常时段"的关键工具，日期拖拽让用户精确定位异常区间。属于增强体验，非核心阻塞。

**Independent Test**: 放大趋势图弹窗，验证 dataZoom 拖拽出现。拖拽选择日期范围，验证图表数据更新。

**Acceptance Scenarios**:

1. **Given** 用户查看趋势图（非放大状态），**When** 鼠标悬停数据点，**Then** 显示 tooltip 展示具体数值
2. **Given** 用户点击趋势图全屏按钮，**When** 弹窗打开，**Then** x 轴显示 dataZoom 拖拽条
3. **Given** 弹窗中趋势图显示 dataZoom，**When** 用户拖拽选择日期范围，**Then** 图表只显示选中范围内的数据
4. **Given** 趋势图非放大状态，**When** 查看图表，**Then** 不显示 dataZoom 拖拽条

---

### User Story 7 - 表格列排序 (Priority: P2)

用户在查看数据明细表格时，可以点击表头对数据进行排序。首次点击按该字段升序排列，再次点击切换为降序，第三次点击恢复默认排序。排序状态通过表头箭头图标指示。

**Why this priority**: 表格排序是数据分析的基础交互能力，帮助用户快速定位极值（最大/最小）、发现异常数据。属于核心交互，但不阻塞基本数据查看。

**Independent Test**: 点击表格的"销售额"列头，验证数据按销售额升序排列。再次点击，验证切换为降序。第三次点击，验证恢复默认排序。

**Acceptance Scenarios**:

1. **Given** 用户查看数据明细表格，**When** 点击"销售额"列头，**Then** 表格数据按销售额升序排列，列头显示向上箭头图标
2. **Given** 表格已按"销售额"升序排列，**When** 用户再次点击"销售额"列头，**Then** 表格数据切换为降序排列，列头显示向下箭头图标
3. **Given** 表格已按"销售额"降序排列，**When** 用户第三次点击"销售额"列头，**Then** 表格恢复默认排序，列头箭头图标消失
4. **Given** 表格已按"销售额"排序，**When** 用户点击"达成率"列头，**Then** 表格切换为按"达成率"升序排列，"销售额"列头箭头消失
5. **Given** 表格处于排序状态，**When** 用户切换筛选条件或翻页，**Then** 排序状态保持，新数据仍按当前排序规则排列

---

### Edge Cases

- 筛选器选项为空时（如无商家数据），下拉框显示"暂无数据"，不报错
- 表格数据为空时，显示"暂无数据"占位提示，分页器隐藏
- URL 参数包含无效的 ID（如 categoryId=9999），页面正常加载，筛选器显示"未知"，表格显示空状态
- 网络请求失败时，显示友好的错误提示和重试按钮
- 页面快速连续切换筛选器时，只显示最新一次请求的结果（避免竞态）
- 全屏弹窗打开时，按 ESC 关闭弹窗，不影响页面其他状态
- 导航栏收起状态下，TOC 位置不受影响

## Requirements *(mandatory)*

### Functional Requirements

**布局与导航**：

- **FR-001**: 系统 MUST 提供左侧固定导航栏，支持手动收起/展开
- **FR-002**: 系统 MUST 在顶部控制栏显示面包屑导航，指示当前页面位置
- **FR-003**: 系统 MUST 在内容区右侧显示 TOC（页内目录），当页面包含 ≥1 个 PageSection 时自动显示
- **FR-004**: 导航栏收起/展开 MUST NOT 影响 TOC 位置和筛选器显示

**筛选器**：

- **FR-005**: 筛选器 MUST 常驻顶部吸顶显示，z-index 确保不被其他元素遮挡
- **FR-006**: 筛选器 MUST 包含日期窗口选择器（近 7 天 / 近 15 天 / 近 30 天）
- **FR-007**: 筛选器 MUST 支持通过 ID 筛选，下拉框显示"ID-名称"格式（如 `1001-红富士`）
- **FR-008**: 筛选器下拉框 MUST 支持搜索功能，输入关键词过滤选项
- **FR-009**: 筛选器选择确认后，URL 参数 MUST 同步更新
- **FR-010**: 页面加载时 MUST 读取 URL 参数，筛选器自动回显对应值
- **FR-011**: 不同页面 MUST 按维度层级显示对应筛选器组合（概览页全部显示，品类页只显示日期+四级类目，等）

**下钻跳转**：

- **FR-012**: 表格中可点击列的名称 MUST 支持点击跳转，携带对应筛选参数
- **FR-013**: 跳转目标页面 MUST 读取 URL 参数并自动填充筛选器
- **FR-014**: 下钻路径 MUST 支持：品类 → 商家 → SKU 三级跳转
- **FR-015**: URL 参数 MUST 使用 `categoryId` / `merchantId` / `skuId` 命名

**表格**：

- **FR-016**: 所有表格 MUST 支持分页，默认每页 20 条
- **FR-017**: 表格表头 MUST 吸顶（sticky），滚动时始终可见
- **FR-018**: 表格滚动条 MUST 在表格对象底部显示
- **FR-019**: 表格 MUST 支持全屏放大功能
- **FR-039**: 表格 MUST 支持列排序，点击表头切换升序/降序/默认，排序状态通过箭头图标指示

**全屏放大**：

- **FR-020**: 表格和可视化图 MUST 提供全屏按钮
- **FR-021**: 点击全屏按钮 MUST 弹出居中弹窗，展示对象完整内容
- **FR-022**: 弹窗 MUST 支持缩放，最多 100%（填满页面），最少为初始弹出大小。初始弹出时缩小按钮失效，放大到最大时放大按钮失效
- **FR-023**: 弹窗 MUST 支持点击外部关闭、ESC 键关闭、关闭按钮关闭
- **FR-024**: 弹窗内表格 MUST 保留分页功能，可独立滚动

**可视化**：

- **FR-025**: 趋势图 MUST 显示 tooltip 和数据标签
- **FR-026**: 趋势图在放大弹窗中 MUST 显示 x 轴日期拖拽功能（dataZoom）
- **FR-027**: 非放大状态 MUST NOT 显示 dataZoom 拖拽

**页面结构**：

- **FR-028**: 各分析页 MUST 包含三个 PageSection：指标概览、趋势分析、数据明细
- **FR-029**: 概览页 MUST 显示数据明细表格
- **FR-030**: 品类分析页 MUST 包含品类表格、商家品类表格、商品表格
- **FR-031**: 商家品类分析页 MUST 包含商家品类表格和商品表格
- **FR-032**: 诊断页 MVP 阶段 MUST 以 placeholder 占位

**设计系统**：

- **FR-033**: 所有组件 MUST 使用 Fresh Produce BI 设计系统 token
- **FR-034**: 色彩 MUST 使用 Primary `#FF6B00`、Secondary `#16b3d3`、Success `#10B981`、Tertiary `#F43F5E`
- **FR-035**: 字体 MUST 使用 Plus Jakarta Sans（标题）和 Inter（正文）

**状态管理**：

- **FR-036**: 筛选器状态 MUST 通过 URL query params 管理
- **FR-037**: 数据缓存 MUST 使用 stale-while-revalidate 策略
- **FR-038**: UI 状态（导航栏收起、全屏弹窗）MUST 使用轻量状态管理

### Key Entities

- **四级类目（Category）**: 品类分类的最基础维度，属性包括 ID 和名称。是所有筛选和下钻的起点。
- **商家（Merchant）**: 商家实体，与四级类目存在多对多关系（一个商家可经营多个品类）。属性包括 ID 和名称。
- **SKU（商品）**: 最小商品单元，归属于特定商家和品类。属性包括 ID 和名称。
- **筛选条件**: 用户选择的筛选参数组合，包括日期窗口、日期范围、四级类目、商家、SKU。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从打开页面到看到完整数据的时间不超过 10 秒（首屏加载）
- **SC-002**: 用户从概览页下钻到商品分析页的跳转操作不超过 3 次点击
- **SC-003**: 筛选器选择后数据刷新时间不超过 3 秒（缓存命中时即时显示）
- **SC-004**: 用户刷新页面后筛选条件 100% 保留（通过 URL 参数）
- **SC-005**: 日复盘时间从 3 小时缩短到 1 小时以内（试运行 4 周后评估）
- **SC-006**: 10 名运营人员中至少 8 名能独立完成从概览到商品的下钻操作（首次使用无需培训）
- **SC-007**: 表格分页、全屏放大、TOC 导航等交互功能 100% 可用，无阻塞性 bug

---

## Assumptions

- 前端开发使用 mock 数据先行，后端 API 就绪后进行数据对接
- 数据卡点（品类市场等级、同簇 SKU 定义等）的确认不影响前端框架开发
- 货盘基础数据模块（依赖卡点 #1：品类市场等级、平台等级及商品关键属性对应门店类型）在当前开发阶段不实现，待数据确认后迭代
- 妙搭脚手架已预装所需依赖（React 19、ECharts、React Query 等），无需额外安装
- 用户通过 Web 浏览器访问，主要使用桌面端（最小分辨率 1280×720）
- 数据量级：单页表格最多 1000 条数据，分页后每页 20 条
- 筛选器选项数量有限（四级类目 < 50，商家 < 200，SKU < 1000），前端搜索即可满足
- 诊断页 MVP 阶段仅占位，具体内容后续迭代
- 品类差异化配置不在 MVP 范围内
- 暗色模式不在 MVP 范围内，但设计 token 需预留扩展能力

---

## Out of Scope (MVP)

- **货盘呈现模块**（当前开发阶段不实现，依赖数据卡点 #1 确认）
- 异常触发流程（自动化异常检测和告警）
- 决策树配置
- 数据门禁自动化（MVP 阶段人工判断）
- 品类差异化配置
- 高代码系统
- 暗色模式
- 移动端适配
- 数据导出功能
- 权限控制（MVP 阶段所有用户权限相同）
