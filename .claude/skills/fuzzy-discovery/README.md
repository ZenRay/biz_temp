# fuzzy-discovery 改进记录

> 基于 2026-10-17 复盘诊断工具 MVP 发现过程的实际执行经验

## 待改进项（高优先级）

### 1. 增加 discovery.md 输出模板

**问题**：skill 只说"最终输出 discovery.md"，但没有定义格式。每次执行都会产出结构不同的文档。

**建议模板结构**：

```markdown
# [项目名] - 发现文档

> 版本：v1.0
> 日期：YYYY-MM-DD
> 状态：发现阶段完成 / 待进入设计

## 一、问题陈述
- 核心问题（1-2 段）
- 问题分布（如有）

## 二、目标用户
- 主要用户（角色 + 痛点）
- 次要用户
- 用户规模

## 三、场景描述
- 参与者
- 复盘对象/操作对象
- 频率与耗时
- 产出物

## 四、当前工作流与痛点
- 当前工具/方法
- 工作流步骤
- 核心痛点（编号列表）
- 时间瓶颈根因

## 五、需求假设（JTBD）
- JTBD-1: When... I want... so I can...
- JTBD-2: ...
- （每个假设附验证方式）

## 六、成功指标
- 基线指标
- 核心目标（可量化）
- 下一步目标（非 MVP）
- 节点目标

## 七、MVP 范围
- 包含（编号列表）
- 不包含（编号列表）
- 技术选型

## 八、机会树
期望结果
├─ 机会 1
│  ├─ 方案
│  └─ 实验
├─ 机会 2
...

## 九、验证计划
- 阶段 1：目标、实验、成功标准
- 阶段 2：...
- 反馈机制

## 十、不做什么
（明确排除的项）

## 十一、风险与缓解
- 风险 1：表现 + 缓解
- 风险 2：...

## 十二、下一步行动
（具体可执行的任务）

## 十三、阶段门禁检查
✅ 问题陈述：明确 / 待补充
✅ 目标用户：明确 / 待补充
✅ 当前障碍：明确 / 待补充
✅ 成功指标：明确 / 待补充
✅ 关键假设：已验证 / 待验证
✅ 验证方式：已设计 / 待设计

**结论**：已达到阶段门禁 / 未达到阶段门禁

## 附录：证据来源
- 会议记录/文档链接
- 外部产物
```

### 2. 增加阶段划分与转换条件

**问题**：10 步工作流是"做什么"，但缺少"什么时候切换"的指引。

**建议阶段划分**：

#### 阶段 1：场景重建（1-2 轮）
**目标**：搞清楚谁、在什么场景、做什么、卡在哪里

**入口条件**：只有模糊描述或症状

**执行步骤**：
- 原始记录（事实/解释/情绪）
- 场景重建（5W1H）
- 角色地图

**出口条件**：
- 能回答"谁、什么场景、期望结果、当前障碍"
- 已知事实 > 未知项

**转换信号**：用户能具体描述一次完整的操作过程

---

#### 阶段 2：问题定义（1-2 轮）
**目标**：找到可控根因，定义 3-5 个候选问题

**入口条件**：场景已清晰

**执行步骤**：
- 因果追问（5 Whys）
- 问题树
- 候选问题定义

**出口条件**：
- 3-5 个候选问题已定义
- 问题不含任何方案
- 用户确认问题优先级

**转换信号**：用户能说出"最紧迫的是 X"

---

#### 阶段 3：需求假设（1-2 轮）
**目标**：将问题转化为 JTBD 假设，设计验证计划

**入口条件**：问题优先级已确认

**执行步骤**：
- 需求假设（JTBD）
- 证据与反证
- 机会树
- 验证计划

**出口条件**：
- 每个假设有验证方式
- 成功指标可量化
- MVP 范围明确（包含/不包含）

**转换信号**：用户能说出"MVP 应该验证 X，成功标准是 Y"

---

#### 阶段 4：输出与门禁（1 轮）
**目标**：生成 discovery.md，通过阶段门禁

**入口条件**：需求假设和验证计划已明确

**执行步骤**：
- 输出 discovery.md（按模板）
- 阶段门禁检查
- 红队质疑（可选）

**出口条件**：
- discovery.md 完成
- 6 项门禁全部 ✅
- 用户确认可以进入设计

**转换信号**：用户说"确认，进入设计"

## 其他改进项（低优先级）

### 假设验证状态追踪
每轮更新假设时标注状态：验证通过 / 待验证 / 部分验证 / 已推翻

### 外部产物登记
当用户提供外部文档（飞书链接、文件等）时，在 discovery.md 附录中登记
